## 1. 현재 실행 처리

- 현재 백그라운드에서 진행 중인 `final_map` 실행 결과까지만 받는다.
- 해당 실행이 끝나면 같은 `map`, `battle`, 호수 E2E를 다시 실행하지 않는다.
- 실패가 있으면 전체 그룹을 재실행하지 말고 실패한 파일·테스트 이름과 로그를 보고한다.
- 구현·단위 시험·캡처가 끝났다면 즉시 `v3_진행보고.md`를 작성하고 멈춘다.

## 2. 금지

- `for ... sleep ...` 방식으로 종료 로그를 반복 감시하지 않는다.
- 출력이 늦다는 이유로 동일 E2E 그룹을 중복 실행하지 않는다.
- 실패 원인을 확인하기 전에 전체 그룹을 재실행하지 않는다.
- 단계 작업 중 전체 순차·전체 병렬 E2E를 실행하지 않는다.
- 이미 통과한 공용 그룹을 같은 단계에서 다시 실행하지 않는다.

## 3. 단계별 검증 상한

1. 구현 중: 변경 파일과 직접 관련된 단위 시험만 실행
2. 기능 완료: 해당 기능 E2E 파일 1회
3. 공용 계약 변경: 영향받은 공용 테스트 파일만 실행
4. 그룹 검증: Codex가 해당 단계에서 명시한 경우에만 1회
5. 전체 검증: C2-8 완료 후보와 main 병합 직전에만 실행

단계별 E2E가 5분을 넘으면 추가 실행을 중단하고 다음을 보고한다.

- 실행 명령
- 경과 시간
- 마지막 완료 테스트
- 멈춘 테스트
- 로그 경로
- 프로세스 종료 여부

## 4. 대기 방식

- 실행 도구가 제공하는 세션 ID나 완료 상태 확인을 사용한다.
- 불가피한 로그 확인은 한 번만 수행한다.
- 장기 실행을 기다리는 동안 반복 셸 루프를 새로 만들지 않는다.
- 60초 이상 상태 변화가 없으면 현재 진행 위치를 기록하고 원인 확인으로 전환한다.
