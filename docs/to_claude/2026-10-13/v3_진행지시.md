## 1. 이번 작업의 완료선

C2-3에서는 다음 세로 흐름을 실제 플레이 가능하게 완성한다.

```text
물풀 미로 진입
→ 젖은 실밥이와 일반 전투
→ 검은 실 덫 제거
→ 붙잡힌 물들이 3명 구조
→ 내부 안전 물길 개방
→ 물풀 미로 정본 장면
→ CH02_MAZE_CLEARED
```

완료 뒤 재접속하면 구조한 물들이, 제거한 덫, 열린 안전 물길이 유지되고 다음 목표는 누비 위기 구간을 가리켜야 한다.

누비 이름 망각 연출, 물먹은 박음이 보스, 물빛 염색실, 성장 단계 2는 시작하지 않는다.

## 3. 임무 배치

기능 맵에 구조 지점 3곳을 둔다. 정확한 좌표는 현재 C2-2 통로·물살·앵커를 기준으로 정하되 다음 조건을 지킨다.

| 지점 | 위치 원칙 | 수호 적 | 학습 목적 |
|---|---|---|---|
| 구조 A | 약한 물살 뒤 첫 마른 발판 근처 | 젖은 실밥이 1 | 전투 후 덫 제거·구조 학습 |
| 구조 B | 깊은 물을 우회하는 얕은 물길 | 젖은 실밥이 1 | 안전 경로 선택 |
| 구조 C | 강한 물살 뒤, 내부 안전 물길 문 앞 | 젖은 실밥이 2 이하 | 배운 규칙 조합 |

- 세 지점이 한 화면에 모두 몰리지 않게 한다.
- 다음 목표 지점은 미니맵과 월드 표식으로 찾을 수 있어야 한다.
- 적·덫·구조 대상이 깊은 물, 벽, HUD 아래에 놓이지 않게 한다.
- 구조 대상은 `turby-muldeuli` 기존 텍스처를 재사용한다.
- 같은 적과 반복 전투를 강요하지 않는다. 이야기 수호 적은 최초 승리 뒤 재생성하지 않는다.

## 5. 젖은 실밥이 전투 계약

기존 서버 전투 규칙과 기존 1인·다인 시간 규칙을 유지한다.

- 1인 전투는 턴·파티 선택 타이머를 끈다.
- 2인 이상일 때 기존 30초 계약을 사용한다.
- 이동은 남은 AP 이내 거리를 한 번에 이동하고 거리만큼 AP를 쓴다.
- 기존 이탈·재접속·미확인 결과 복원·중복 보상 방지를 그대로 적용한다.
- 스타터 누비만으로 무난히 이길 수 있게 조정한다.
- 구조 A/B 전투는 기본 공격을 이해하면 2~3회의 유효 공격으로 끝나는 수준으로 둔다.
- 구조 C도 총 전투 시간이 A/B의 1.5배를 크게 넘지 않게 한다.
- 포획·확률 보상·통화 보상은 없다. 이야기 진행 증거만 남긴다.

젖은 실밥이의 장 특징은 하나만 추가한다.

### 젖은 속박

- 실밥이의 지정 공격이 적중하면 대상에게 `wet_bind` 1회를 건다.
- 다음 이동 행동의 이동 가능 거리만 1칸 감소하고 즉시 해제된다.
- 이동 가능 거리는 최소 1칸을 보장한다.
- 공격·아이템·턴 종료는 막지 않는다.
- 같은 대상에게 중첩하지 않고 지속 시간을 갱신하지 않는다.
- 보스용 영구 상태나 복잡한 해제 아이템을 추가하지 않는다.

물 밖 유인에 따른 방어력 감소는 이번 기능 맵에 전투 지형 경계가 명확히 없으므로 임의 구현하지 않는다. 후속 전투 지형 확장 대상으로 보고에 남긴다.

## 6. 덫과 구조의 서버 권위 계약

구조 지점마다 안정적인 ID를 둔다.

```text
lake_rescue_a
lake_rescue_b
lake_rescue_c
```

각 지점은 다음 상태를 갖는다.

```text
guard encounter id
trap bounds / interaction radius
rescued event id
```

개별 영구 사건:

```text
lake_trapped_mulduri_a_rescued
lake_trapped_mulduri_b_rescued
lake_trapped_mulduri_c_rescued
```

검증 순서:

1. 플레이어가 해당 구조 지점 반경 안에 있음
2. 해당 지점의 서버 전투 결과가 승리·정산 완료됨
3. 아직 구조하지 않은 지점임
4. 서버가 덫 제거와 구조 사건을 한 트랜잭션으로 기록

클라이언트가 구조 ID, 전투 승리, 덫 제거 완료를 임의로 확정하지 않는다. 다른 지점의 승리 증거를 재사용할 수 없다.

개별 구조는 중복 보상이 없고 별도 아이템·통화를 지급하지 않는다. 세 구조 상태는 재접속·방 재생성 뒤에도 이벤트로 복원한다.

## 7. 집계 사건·안전 물길·체크포인트

세 개별 구조 사건이 모두 완료되면 서버가 다음을 처리한다.

1. `lake_trapped_turbies_rescued` 1회 기록
2. 미로 내부 안전 물길 목표 활성화
3. 안전 물길 지점에서 `docs/scene/2장.md`의 `물풀 미로` 대사·서술 구간 재생
4. 해당 구간을 끝까지 확인하면 `lake_safe_route_opened` 기록
5. 내부 안전 물길 문을 열고 `CH02_MAZE_CLEARED`로 이동

4~5는 한 트랜잭션으로 처리한다. 직접 사건 완료 요청은 거부하고 서버의 세 구조 사건과 안전 물길 지점 증거를 요구한다.

안전 물길은 C2-2의 **미로 입구 문**과 별개인 내부 출구다.

- 새 gate ID: `gate_lake_safe_route`
- 닫힘: `reed-gate-closed`
- 열림: `reed-gate-open`
- 열림 조건: `lake_safe_route_opened`
- 열린 뒤 C2-4 시작 지점까지 통행 가능
- C2-4 장면은 아직 재생하지 않음

재접속 상태:

- 일부 구조: 완료한 대상·덫·적만 사라지고 다음 미완료 구조를 가리킴
- 세 구조 완료, 장면 미완료: 안전 물길 상호작용 앞에서 계속
- `CH02_MAZE_CLEARED`: 내부 문 열린 상태, 다음 목표는 염색 샘 방향의 누비 상태 확인

## 8. 정본 장면

`docs/scene/2장.md`의 `물풀 미로` 구간을 문구와 순서대로 런타임 데이터로 옮긴다.

- 물들이의 기계음 설명
- `타닥, 타닥, 타닥……`
- 푸른 실이 잘리는 서술
- `{playerName}`과 누비 대화

세 구조가 끝나기 전에 이 장면을 재생하지 않는다. 장면을 끝까지 확인하기 전에 새로고침하면 처음부터 다시 볼 수 있어야 하며, 체크포인트와 안전 물길은 아직 완료 처리하지 않는다.

## 9. 월드 덫 동작

미구조 지점의 검은 실 덫은 쉽게 알아볼 수 있는 위험 요소로 동작한다.

- 밟으면 서버가 1,200ms 동안 이동 속도를 50%로 제한한다.
- 이 상태에서 물살을 맞으면 해당 1회 밀림 거리만 +32px 한다.
- 적용 뒤 속박과 추가 밀림 효과는 해제된다.
- 중첩하지 않는다.
- HP·아이템·진행도 손실은 없다.
- 구조 완료 뒤 해당 덫은 사라지고 다시 발동하지 않는다.
- 서버가 덫 진입·지속·소비를 판정하며 클라이언트는 짧은 실 고리 연출만 표시한다.

전투의 `wet_bind`와 월드 덫 상태는 서로 다른 상태이며 저장하거나 공유하지 않는다.

## 11. 시험

### 단위·통합

1. 세 구조 지점·적·덫·내부 문이 지도 안이며 벽·깊은 물과 겹치지 않음

5. 다른 지점 승리 증거와 위조 구조 요청 거부
6. 전투 승리 전 구조 거부

8. 부분 구조 상태 재접속 복원

12. 열린 안전 물길과 제거된 덫 재접속 유지
13. 월드 덫 속도 제한·물살 +32px·1회 소비·비중첩
14. 다른 플레이어의 구조·덫·전투 상태가 섞이지 않음
15. 패배·이탈·새로고침·중복 결과로 구조를 위조할 수 없음

### 13.1 검증 속도 정책

- 구현 중에는 변경 파일과 직접 관련된 단위 시험만 실행한다.
- 기능 완료 뒤 C2-3 전용 E2E 파일을 1회 실행한다.
- 단계별 E2E 목표 시간은 2분 안팎이며 **5분을 넘으면 중단하고 보고**한다.
- 실행 상태가 60초 동안 변하지 않으면 반복 대기하지 말고 멈춘 테스트와 로그를 확인한다.
- `for`, `while`, `sleep`을 사용한 종료 로그 반복 감시는 금지한다.
- 출력이 늦다는 이유로 동일 E2E를 중복 실행하지 않는다.
- 실패가 발생하면 원인을 확인하고 수정한 뒤 실패한 파일만 1회 재실행한다.
- 이미 통과한 단위 시험·E2E·공용 그룹은 같은 단계에서 다시 실행하지 않는다.
- 캡처는 C2-3 E2E 실행 중 함께 생성하며 캡처만을 위한 전체 흐름 재실행을 하지 않는다.

5분 초과 또는 멈춤이 발생하면 보고서에 다음을 기록한다.

```text
실행 명령
시작 시각과 경과 시간
마지막 완료 테스트
멈춘 테스트
로그 경로
프로세스 종료 여부
```

검증 결과에는 다음 표를 반드시 포함한다.

```text
| 검증 항목 | 최초 시간 | 재실행 횟수 | 재실행 이유 | 최종 결과 |
```

재실행이 없으면 `0회`라고 적는다. 백그라운드 실행은 시작·종료 시각과 종료 코드를 기록한다.
