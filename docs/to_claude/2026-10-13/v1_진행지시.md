## 3. 이번 세로 흐름

### 3.1 입장 조건

- `CH01_COMPLETE`를 서버가 확인한 플레이어만 2장 이야기를 시작할 수 있다.
- 백필된 호수 입장 권한만 있고 `CH01_COMPLETE`가 없으면 자유 탐험만 가능하며 2장 이야기 이벤트는 거부한다.
- 1장 미완료 계정은 2장 이벤트를 URL·소켓·직접 요청으로 시작할 수 없다.

### 3.2 체크포인트

이번 작업에서 구현·검증할 상태:

1. `CH02_STARTED`
2. `CH02_SETTLEMENT_MET`

서버 전이 예시 이름은 현재 명명 규칙을 조사해 확정하되 의미는 아래와 같아야 한다.

- 호수 입구 도착과 도입 대화 완료 → `CH02_STARTED`
- 물들이 대화와 물결북 반응 확인 → `CH02_SETTLEMENT_MET`

클라이언트가 도착 체크포인트를 직접 지정하지 않는다. 기존 1장과 같은 서버 이벤트 전이표를 사용한다.

### 3.3 장면

`docs/scene/2장.md`의 다음 두 구간을 문구·순서 그대로 런타임 대화 데이터로 옮긴다.

- `물빛 입구`
- `색을 잃은 정착지`

요구사항:

- `{playerName}` 치환
- 누비·물들이 화자 구분
- 대사 전후 서술 유지
- 도입부 검은 실 연출과 물결북 반응을 안정적인 cue ID로 표현
- 새 초상화·사운드가 없으면 기존 폴백을 사용
- 미작성 문구를 임의로 추가하지 않음

## 4. 서버 구현

기존 일반화된 이야기 테이블을 재사용하고 새 DB 테이블·컬럼을 만들지 않는다.

- 2장 이벤트 두 개를 서버 전이표에 추가
- 허용 시작 상태와 선행 이벤트 검증
- `CH01_COMPLETE` 검증
- 동일 이벤트 직렬·동시 요청의 멱등성
- 잘못된 순서, 다른 플레이어, 미완료 1장 요청 거부
- 체크포인트별 다음 대화 구간 반환
- 재접속 시 완료된 구간을 반복하지 않음
- 이번 두 이벤트에는 아이템·통화·성장 단계 보상이 없음

2장 전체 보상인 물빛 염색실과 성장 단계 2는 아직 구현하지 않는다.

## 5. 클라이언트·맵 구현

- 2장 카드가 열린 계정이 호수에 입장하면 호수 입구 트리거에서 도입 대화를 재생
- 도입 완료 뒤 정착지의 물들이·물결북 목표를 표시
- 물들이 상호작용으로 두 번째 구간 재생
- 물결북 반응 후 목표를 `물결북의 파문을 따라 물풀 미로로 가자`로 갱신
- 미로 입구는 다음 작업 대기 상태로 닫고 `물풀 미로는 다음 개발 단계에서 열립니다` 같은 개발 문구를 게임 화면에 노출하지 않는다.
- 자연스러운 정본 문구로 진행 대기 상태를 표시한다. 권장: `물결북의 파문이 향한 물풀숲을 살펴보자.`
- 모바일 640×360에서 대화·목표·상호작용 버튼이 HUD와 겹치지 않게 기존 반응형 배치를 재사용

개발 전용 순간이동이나 체크포인트 주입 버튼을 운영 화면에 추가하지 않는다.

## 6. 기능 맵 데이터

2장 단일 맵의 최소 데이터만 만든다.

- 시작 지점
- 호수 입구 이야기 트리거
- 정착지의 물들이 위치
- 물결북 위치와 상호작용 반경
- 다음 작업의 물풀 미로 입구 경계
- 기본 이동 가능 영역과 최소 충돌 영역

좌표는 기능 검증용으로 명확히 분리하고 최종 미술 좌표라고 표시하지 않는다. 서버와 클라이언트가 같은 맵 계약을 사용한다.

## 7. 시험 우선순위

### 단위·통합

- 1장 완료 여부에 따른 2장 진행 허용·거부
- `CH02_STARTED`와 `CH02_SETTLEMENT_MET` 순서
- 직렬·동시 중복 완료 멱등성
- 두 대화 구간의 항목 순서와 `{playerName}` 치환
- 체크포인트별 재접속 구간
- 물들이·물결북 상호작용 거리
- 서버·클라이언트 맵 좌표 계약

### E2E

새 E2E 파일 또는 기존 story 그룹에 다음 한 흐름을 추가한다.

1. 1장 완료 상태에서 호수 입장
2. 도입 대화 완료
3. 새로고침 후 도입 대화가 반복되지 않음
4. 물들이에게 이동·상호작용
5. 물결북 반응과 목표 갱신
6. 다시 새로고침해 `CH02_SETTLEMENT_MET`에서 복원
7. 1280×720과 640×360에서 필수 UI 확인
