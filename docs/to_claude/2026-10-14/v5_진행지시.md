## 1. 이번 작업의 단일 완료선

최종 배경을 수정하지 않고, 2장의 모든 이동·충돌·수역·사건 좌표를 배경의 실제 길과 물 경계에 맞춰 처음부터 끝까지 플레이 가능하게 한다.

```text

```

정본 사건 순서, 상태 ID, 보상, 전투 규칙은 바꾸지 않는다.

## 3. 구현 범위

### 3.1 이동 지형과 충돌

- blocker를 배경의 물풀 섬·암초·외곽 경계에 맞춰 다시 배치한다.
- 이동 가능한 모래길과 얕은 물 통로를 blocker가 가로막지 않게 한다.
- 시각적으로 막힌 장식·섬을 통과할 수 없게 한다.
- 깊은 물 판정은 실제 어두운 물 영역 안으로 옮기고, 모래길이나 얕은 통로를 덮지 않게 한다.
- 각 진행 상태에서 입구부터 현재 목표까지 최소 한 개의 연속 경로를 보장한다.

기존의 큰 사각형 몇 개로 배경을 억지로 덮지 않는다. 필요한 경우 작은 사각형 또는 기존 계약이 지원하는 다각형 묶음으로 경계를 근사한다. 충돌 조각끼리 틈이 생겨 장식 안으로 빠지거나 길을 막지 않게 한다.

### 3.2 문·물살·앵커

- `gate_reed_maze`, `gate_lake_safe_route`를 시각적 좁은 길목에 맞춘다.
- `currentFields`를 서버 데이터에서 읽어 디버그 오버레이에 표시하고, 배경의 물결 방향·얕은 물 통로와 맞춘다.
- 물살은 플레이어를 blocker나 깊은 물 안으로 밀어 넣지 않는다.
- safe anchor는 실제 육지나 안전 통로 위에 둔다.
- 복원·재접속 시 현재 체크포인트에서 가장 가까운 유효 안전 위치로 복구한다.

### 3.3 사건·NPC·목표 좌표

C2-7A 권장 좌표를 시작점으로 쓰되, 최종 결정은 디버그 오버레이와 실제 플레이 동선으로 검증한다.

- `lake_nubi_crisis`, `lake_boss_entrance`, `anchor_maze_exit`, `lake_wave_drum`은 C2-7A에서 허용 범위였으므로 불필요하게 이동하지 않는다.
- 좌표 변경 뒤 클라이언트 표시와 서버 판정이 같은 데이터 또는 동일 계약을 사용하게 한다.

### 3.4 디버그 오버레이

기존 오버레이에 `currentFields`를 추가한다. 캡처에서 다음 항목을 색과 범례로 구분한다.

- blocker
- gate
- deep/shallow water
- current field와 힘 방향
- safe anchor
- story/rescue/trap/NPC 지점과 작동 반경

개발 모드 전용이며 일반 화면과 운영 번들에는 노출하지 않는다.

## 4. 서버 권위·재접속·멱등 계약

- 이동 가능 여부, gate, 깊은 물, current, 안전 복원 좌표는 서버가 판정한다.
- 클라이언트 표식과 충돌 표현은 서버 계약을 시각화하며 별도 규칙을 만들지 않는다.
- 좌표 보정 때문에 완료한 구조·사건·보스·보상을 다시 지급하지 않는다.
- 기존 체크포인트와 상태 ID를 유지한다.
- 이전 좌표에 저장된 진행 중 사용자가 접속해도 새 유효 경로의 안전 anchor로 복구되어야 한다.
- 기존 C2-1~C2-6 정본 순서와 `CH02_COMPLETE` 결과를 유지한다.

## 5. 수치 통과 기준

1. 핵심 사건·NPC·문·앵커 중심은 시각적 모래길 또는 허용된 얕은 물 통로 안에 있어야 한다.
2. 핵심 지점과 시각 길 중심의 차이는 80px 이하를 목표로 한다.
3. blocker가 주 이동로와 겹치는 면적은 0이다.
4. 깊은 물 판정이 모래길을 가로지르는 구간은 0이다.
5. 필수 진행 경로의 실제 통과 폭은 플레이어 충돌 지름 + 좌우 각 12px 이상이다.
6. 3개 구조 지점, 안전 물길, 누비 위기, 보스 입구는 각 상태에서 도달 가능하다.
7. 물살 적용 뒤 blocker·깊은 물 안에 갇히는 경우는 0이다.
8. 일반 화면에서 HUD와 목표·플레이어의 교차는 0이다.

색 분류 스크립트의 근사값만으로 통과시키지 않는다. 실제 디버그 캡처와 플레이 결과를 함께 사용한다.

## 6. 최소 시험

### 단위·계약 시험

1. 입구→정착지→미로→염색샘 연결 경로 존재
2. 각 진행 상태에서 다음 필수 목표 도달 가능
3. blocker와 필수 이동 경로 교차 0
4. 깊은 물과 필수 육상 경로 교차 0
5. current 적용 후 결과 좌표가 유효 이동 영역
6. 구 좌표 저장값의 안전 anchor 복구
7. 클라이언트와 서버의 gate·anchor·사건 좌표 일치
8. 기존 상태 ID·사건 순서·보상 정의 불변

### 기능 전용 E2E

`lake-final-layout.e2e.ts` 한 파일만 만들거나 기존 전용 파일을 이 이름으로 분리해 1회 실행한다.

1. 새 게임 상태에서 입구→정착지→구조 3개→안전 물길→누비 위기→보스 입구까지 실제 이동하고, 잘못된 벽·깊은 물 끼임 없이 도달
2. 미로·안전 물길 중 재접속하여 유효 anchor 복구 후 다음 목표 도달

E2E는 전투 승패와 보상 정산을 다시 검증하지 않는다. 필요한 상태는 승인된 테스트 시드로 준비한다.

## 8. 검증 속도 정책

- 구현 중에는 변경한 호수 좌표·충돌·이동 계약의 직접 관련 단위 시험만 실행한다.
- 기능 완료 시 `lake-final-layout.e2e.ts` 한 파일을 1회 실행한다.
- `story`, `map`, `battle`, `visual`, `layout-qa` 그룹 전체와 전체 E2E는 실행하지 않는다.
- E2E 목표는 2분 안팎, 5분 초과 시 즉시 중단하고 마지막 완료 시험·멈춘 시험·로그·프로세스 상태를 보고한다.
- 상태 변화 없는 대기는 60초 뒤 원인 확인으로 전환한다.
- `for`, `while`, `sleep` 반복 종료 감시를 금지한다.
- 실패를 수정한 뒤 실패한 시험 파일만 1회 재실행한다.
- 캡처는 전용 E2E 실행 중 생성하고 캡처만을 위한 전체 재실행을 하지 않는다.
- 보고서에 아래 표를 반드시 넣는다.

```text
| 검증 항목 | 최초 시간 | 재실행 횟수 | 재실행 이유 | 최종 결과 |
```
