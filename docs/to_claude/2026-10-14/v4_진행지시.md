## 3. 렌더링

- 호수 지역만 `lake-base`를 사용한다.
- 기존 회색상자 바닥, 격자, `물풀 벽`, `깊은 물` 같은 개발용 글자를 운영 렌더에서 숨긴다.
- 얕은 물·깊은 물 색면의 코드 도형도 운영 화면에서 숨긴다.
- 물결북·물풀문·물살·덫·물들이·적·목표·플레이어는 기존 상태 에셋으로 배경 위에 유지한다.
- 개발 모드에서는 충돌 사각형·문·깊은 물·앵커·물살 영역을 반투명 선으로 켜고 끌 수 있게 기존 디버그 경로를 사용한다.
- 디버그 오버레이는 운영 빌드와 일반 캡처에 나타나지 않는다.

## 5. 정합성 측정

네 구역에서 일반 화면과 디버그 화면을 비교한다.

| 구역 | 기준 중심 |
|---|---:|
| 숲 연결 입구 | `(380,2040)` |
| 호숫가 정착지 | `(820,1220)` |
| 물풀 미로 | `(1760,1380)` |
| 염색 샘 | `(2700,600)` |

각 구역에서 다음을 표로 보고한다.

1. 플레이어가 시각적 육지·길 위에 있는지
2. 서버 blocker가 배경의 물풀·바위 경계와 맞는지
3. 깊은 물 판정이 어두운 물 영역 안에 있는지
4. 문·덫·NPC·보스 지점이 열린 공간에 있는지
5. 주 이동로의 시각 폭과 실제 통과 폭
6. 배경 길 중심과 기능 동선 중심의 최대 차이(px)
7. C2-7B에서 이동이 필요한 대상과 권장 이동량

판정 기준:

- 핵심 지점이 시각적 깊은 물·장식 안에 들어가면 불합격
- 배경 길 중심과 기능 동선 차이 80px 이하는 허용
- 81~160px는 C2-7B 보정 대상
- 160px 초과는 구역 단위 재배치 대상으로 보고

## 6. 시험

### 단위

1. `lake-base` 파일·키·3200×2400·해시
2. 호수만 최종 배경을 사용하고 다른 지역은 기존 배경 유지

4. 운영 렌더에서 개발 격자·벽 글자·깊은 물 글자 0
5. 디버그 오버레이가 개발 모드에서만 표시
6. 기존 기능 좌표 JSON이 `51370ab...` 기준과 동일

### 최소 E2E

`lake-final-art.e2e.ts` 한 파일에 2건만 둔다.

1. 1280×720: 입구→정착지→미로→염색 샘 카메라 이동과 일반 캡처
2. 640×360: 네 구역 일반 화면, HUD 교차와 배경 경계 확인

디버그 캡처는 같은 1280 실행에서 토글해 생성하며 별도 E2E를 만들지 않는다.
