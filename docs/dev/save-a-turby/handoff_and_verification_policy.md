# 터비 구하기 — 보체일전 및 검증 속도 정책

시행일: 2026-10-13  
적용 대상: Codex가 Claude에게 전달하는 모든 개발 일감 지시서

## 1. 보체일전의 의미

`보체일전`은 다음 순서를 뜻한다.

1. **보고 확인**: Claude의 최신 보고서·커밋·변경 범위·작업 트리 상태를 확인한다.
2. **체크**: 정본, 서버 권위, 에셋, 캡처, 시험 결과를 실제 증거와 대조한다.
3. **일감 전달**: 승인·조건부 반려·반려를 명시하고 다음 한 단계의 지시서를 작성한다.

검수 없이 다음 일감을 먼저 전달하지 않는다. 조건부 반려 시 다음 기능 단계 대신 보완 작업만 전달한다.

## 2. 모든 일감 지시서의 필수 절

앞으로 작성하는 모든 `진행지시`, `검수결과`, `보완지시` 문서에는 아래 항목을 포함한다.

1. 이전 단계 판정과 승인 SHA
2. 이번 단계의 단일 완료선
3. 구현 범위와 금지 범위
4. 정본·에셋 경로
5. 서버 권위와 재접속·멱등 계약
6. 최소 시험 목록
7. **검증 속도 정책**
8. 캡처 목록
9. 커밋·보고 경로

## 3. 검증 속도 정책 — 지시서에 그대로 포함할 기준

### 실행 계층

| 시점 | 허용 검증 |
|---|---|
| 구현 중 | 변경 파일과 직접 관련된 단위 시험 |
| 기능 완료 | 해당 기능 전용 E2E 파일 1회 |
| 공용 계약 변경 | 영향받은 공용 시험 파일만 실행 |
| 그룹 검증 | Codex가 지시서에 그룹명을 명시한 경우 1회 |
| 전체 E2E | 장 완료 후보와 main 병합 직전 |

### 시간 상한

- 단계별 E2E 목표: 2분 안팎
- 단계별 E2E 중단 기준: 5분
- 상태 변화 없는 대기: 60초 뒤 원인 확인으로 전환
- 동일 그룹 재실행: 실제 실패를 수정한 뒤 1회만 허용

5분을 넘으면 추가 대기·재실행을 중단하고 다음을 보고한다.

```text
실행 명령
시작 시각과 경과 시간
마지막 완료 테스트
멈춘 테스트
로그 경로
프로세스 종료 여부
```

### 금지

- `for`, `while`, `sleep`을 사용한 반복 종료 감시
- 출력이 늦다는 이유의 동일 E2E 중복 실행
- 실패 원인 확인 전 전체 그룹 재실행
- 단계 개발 중 전체 순차·전체 병렬 E2E
- 이미 통과한 공용 그룹의 같은 단계 재실행
- E2E용 기능을 운영 UI에 추가

### 보고 필수 표

```text
| 검증 항목 | 최초 시간 | 재실행 횟수 | 재실행 이유 | 최종 결과 |
```

재실행이 없으면 `0회`라고 명시한다. 백그라운드 실행은 시작·종료 시각과 종료 코드를 함께 기록한다.

## 4. 일감 크기 제한

- 한 지시서는 하나의 플레이 가능한 세로 흐름만 다룬다.
- 기능 구현, 최종 미술, 전체 회귀 검증을 한 단계에 함께 넣지 않는다.
- 전투 엔진과 월드 이동 엔진을 함께 변경해야 하면 시험은 각 기능 전용 파일로 제한한다.
- 예상 구현과 최소 검증 합계가 20분을 크게 넘는 범위는 두 단계로 나눈다.
- 캡처는 E2E 실행 중 함께 생성하여 별도 전체 재생을 피한다.

## 5. Codex 검수 원칙

- 통과 수만 보지 않고 정본 사건명과 체크포인트 의미를 확인한다.
- 캡처는 직접 열어 가독성과 HUD 교차를 확인한다.
- 전체 시험을 독립 재실행하지 않는다. 위험이 있는 최소 단위만 재검증한다.
- 장시간 시험 결과가 없어도 구현 증거를 먼저 검수하고, 필요한 최소 검증만 지정한다.
- 승인 뒤 다음 일감에는 이 문서의 검증 속도 정책을 요약해 본문에 직접 포함한다.
