# 전략 알까기 - 게임 기획안 (v1)

> 게임 프로젝트(Hub: React + Phaser 3, Canvas 삽입 방식) 내 3번째 게임

## 1. 개요
- 방장이 방 생성 시 **참가자 수**, **알 개수**를 설정
- 인원 구조: **2인 이상** (가변 인원, 1:1 고정 아님)
- 방(room) 단위로 N명이 동시 접속하여 대전

## 2. 진행 방식
- **턴제 + 턴 내 동시 처리**
  - 전 참가자가 각자 알을 골라 팅기는 행동을 완료
  - 전원 행동 완료 시점에 물리 이동/충돌을 **동시 처리**
- 턴 제한시간: **20초**
  - 시간 초과 시 해당 참가자는 행동 없이 턴 넘어감
- 제한 턴 수 이내 진행 (최대 턴 수는 미정)

## 3. 전략 요소
| 요소 | 내용 |
|---|---|
| 지형지물 | 보드 내 배치, 알을 숨기는 용도로 활용 가능 |
| 지불(비용) | 액션 수행 시 리소스 소모 (소모 대상/종류 미정) |
| 알 무게(저항도) | 알마다 무게가 다름. **알 주인만 자신의 무게 확인 가능** (상대는 비공개 → 정보 비대칭 전략 요소) |

### 물리 규칙
- 무거운 알: 버티는 힘 큼 → 맞은 상대 알이 더 크게 튕겨나감
- 가벼운 알: 이동은 용이하나 버티는 힘 약함

## 4. 득점
| 조건 | 점수 |
|---|---|
| 상대 알을 판 밖으로 아웃 | 100점 |
| 단순 명중(아웃 아님) | 20점 |

## 5. 승리 조건
- 제한 턴 수 내 **최다 점수** 획득 시 승리

## 6. 알 개수 제한
- 고정 개수가 아닌, **보드 크기 내 수용 가능한 총알 개수로 제한** (인원수에 비례하여 산정)

## 7. 통신/아키텍처 (참고 - 별도 논의중)
- 방 단위(N인) 브로드캐스트 필요
- 단일 서버 기준: room별 소켓 목록(Map) 관리로 구현 가능
- Redis Pub/Sub 등 외부 브로커 필요 여부는 **스케일아웃(서버 다중화) 계획 확정 시** 재결정 예정
- 현재 스케일아웃 계획 없음 (변경 가능성 있어 재확인 필요)

## 8. 미확정 항목 (추가 논의 필요)
- [ ] 지불(비용) 시스템의 구체적 소모 대상/종류 (액션 포인트 / 알 개수 / 별도 자원 등)
- [ ] 최대 턴 수
- [ ] 보드 크기(가로x세로 또는 형태)
- [ ] 지형지물의 종류 및 개수
- [ ] 알 무게 값의 범위/분포 (예: 3단계인지 연속값인지)
- [ ] 지불 시스템과 알 선택/팅기기 액션 간의 연동 방식

## 9. 알(기물) 비주얼 개선안 (v2 논의, 2026-09-14)

기존 구현은 바둑알 스타일(구형 그라디언트, 9색 팔레트)이었으나, 아래와 같이 방향 전환을 논의함.

### 최대 인원 축소
- **9인 → 5인**으로 축소
- 팔레트도 9색 → 구분이 뚜렷한 5색으로 축소 (예: 백/흑/적/청/녹)
- 영향 범위: BE `MAX_PLAYERS`, 방 생성 UI 인원수 선택지, `createStartingPositions`(시작 위치 배치), `PLAYER_COLORS` 상수

### 기물 형태 변경
- 바둑알(구형 그라디언트) → **체커(서양 장기) 기물 형태**로 변경
- 위에서 내려다보는 2D 뷰 기준: 납작한 원판 + 베벨(동심원 테두리)로 입체감 표현

### 플레이어 차별화: 레이어 구조
색상만으로 구분하던 방식에서, **문양(엠블럼)을 추가한 2단 레이어 구조**로 차별화하기로 함.
- **베이스 레이어**: 체커 기물 형태(원판+베벨), 전 플레이어 공통 형태, 색상은 팔레트에서 틴트(tint)로 적용
- **엠블럼 레이어**: 베이스 위에 플레이어 고유 문양(점/줄무늬/십자 등, 실루엣만)을 오버레이 — 색맹 접근성 + 시각적 재미 목적
- 에셋 수 절약: 베이스 PNG 1장(틴트로 5색 처리) + 문양 PNG 5장(플레이어별) 조합, 색상별 개별 PNG 9~5장을 따로 만들 필요 없음
- 구현 시 기존 장애물(rock/tree/car) SVG 로딩 패턴(`this.load.svg`/이미지 + `setDisplaySize`)을 재사용 가능

### 지켜야 할 제약 (기존 설계 원칙 유지)
- ⚠️ **문양/패턴은 "플레이어 소속"만 나타내야 하며, 무게(저항도) 정보를 암시해서는 안 됨**
  - 같은 플레이어의 알은 무게와 무관하게 항상 동일한 문양 사용
  - 무게는 여전히 알 주인만 확인 가능한 비공개 정보 (3장 정보 비대칭 전략 요소 유지)
